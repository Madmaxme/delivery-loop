# Conduct

The runner prepends this file to every ground and build prompt. An install does not replace it.

- One code path. Extend the owner of a behavior. Do not add a second implementation that can disagree with it.
- If a behavior already has an owner, every caller uses that owner. Change that owner first. Repeating the rule in a screen, a default argument, or another constant is unfinished. The subject does not matter.
- A measure the owner does not claim stays separate. A change that belongs in one place does not get a new shared owner.
- When extending an owner, include the remaining callers that still do the old behavior, or name a category exclusion.
- Evidence before building. A live incident is a disagreement between what should have happened and what the system that owns the outcome shows. The subject does not matter. Name the explanations that could produce it, including one where this repository's code is innocent. Run a probe that could kill the explanation you currently favor. While two records still disagree, that probe was the wrong one and the verdict stays NEEDS DIAGNOSIS. A code change is allowed only after a probe shows the outside system did what we asked and this repository's code did something else. A cited query is the start of that investigation, not the end. The handoff says `**Evidence:** queried` when a live system was read, and `**Evidence:** not-applicable` when nothing is already wrong. `queried`, and a legacy `**Runtime evidence:** queried`, require `**Killed alternatives:**` with a `probe:` for each explanation that probe killed. `not-applicable` is unfinished when a live system was read. A missing killed-alternatives line, `none`, or `not-applicable` beside a cited query does not build.
- The work order cites one invariant that already exists in the install's invariants file. The change keeps that rule true.
- Tests named in the work order must pass before merge. The install's quality check must be green.
- A one-off patch that leaves the wrong rule in place is unfinished. Change the owner of the rule.
- A required step that returned no has one heal. Sweep, ship, land, and every other required step use that same heal. The heal answers `**Heal:**` edit, wait, or login. edit changes that step's owner. wait runs the step again. login replaces the login and runs the step again. A different failure is a different heal. A repeated no keeps that owner. This page edits once and ends so the edited trunk loads. The next page heals again until that failure type's cap is recorded on the ticket. The owner may be the ticket branch, this checkout, a repo the command ships, or the package that executes this loop. When that owner is the package that executes this loop, edit opens a pull request on branch `engine-heal/<ticket>` with the label `engine-heal`. Routine heals remain patch-only through the highest-tag helper. The planned v2.0.0 release is the separately authorized greater-version bump over main's current package version, not the routine helper's output. The opener pushes with the commit-actor token. The `pull_request` quality check gates that head. The engine-heal workflow squash-merges and is the only tag and release writer. A pull request without a greater version gets a comment and stops. A client pins the tag when it needs the change. When the owner is anything else, edit lands that trunk. An open pull request is not landed. A ship-stage promotion or continue uses the same rule. A note or a side watcher is not the fix.
- Do not invent a product question. Stop with NEEDS DIAGNOSIS, NEEDS RESCOPE, WRONG DIAGNOSIS, or ALREADY SHIPPED when the ticket is not BUILDABLE.
- A BUILDABLE audit says `**Prior request:** none`, `kept`, `replaced <id>`, or `ask`. `none` means no written rule asked for the current behavior. `kept` means one did and this ticket keeps it. `replaced <id>` means this ticket undoes that request and names it. `ask` means a rule asked for the current behavior and this ticket does not undo it. The runner records `ask` as `kept`. A missing line, or `replaced` without an id, does not build. `ask` with no symbols closes as already done. `ask` with symbols uses the same land path. The verdict stays BUILDABLE. Look only at the install's invariant and decision documents and at commit subjects that already name a ticket. No sentence means `none`. Do not wait on `needs-product`. A missing default is a normal ticket on this path.
- A BUILDABLE audit says `**Outside grant:** none` or `open`. `none` means the done-state is code this repository can land. `open` means the done-state is something this repository cannot obtain: a vendor approval, an account only a person can create, or an engine this repository does not own. Build the owned code either way. `open` does not mark the ticket complete, so anything blocked by it stays blocked. Reading a vendor's documentation is not that grant.
- `**Repos:**` names land repos from the runner's land-repo list. The directory the agent was started in is not a land repo unless that name is on the list.
- A BUILDABLE audit says `**Journey evidence:** recorded`, `not-applicable`, or `blocked`. `not-applicable` means the done-state is not a journey a person walks. `recorded` means it is. A web journey cites an https recording or screenshot URL that also appears in the build receipt. The build handoff puts that raw URL in backticks and omits the `**Journey proof:**` prefix. The journey command prints that prefix. Capture it on the running build and publish an https URL. Use a non-mutating view or test data. A mobile journey cites a route test, `repo/path_test.dart` or `repo/path.test.ts`, that is on the exact landed commit and whose path matches `journeySpec`; configured delivery-stage refs count only after their exact-SHA receipts pass. A spec outside that pattern is not proof. A sentence with no token is not proof. Missing proof after landing blocks completion until the original build receipt or a client-owned verifier supplies valid evidence; a later run does not start a generic worker to capture it. Validated v2 `proof-receipt` markers may be reused only for the current `criteriaRevision` and exact landed SHAs. `blocked`, or a missing line, does not build or mark the ticket complete.

The install owns the concrete proof: end-to-end type safety, which file is the source of truth, when a module should split, and making a shared primitive safe for every caller before the feature uses it. Those rules live in the install's invariants and prompt files.
